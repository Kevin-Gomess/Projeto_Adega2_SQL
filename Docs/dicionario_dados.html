Dicionário de Dados - Adega do Tonho

Este documento apresenta as tabelas, os atributos, os tipos de dados, as descrições e as regras de negócio do banco de dados da Adega do Tonho.

SGBD: MySQL 8.0

Modelo de referência: Modelo lógico enviado em XML, com 19 entidades.

1. Convenções utilizadas

  • PK: chave primária, identifica cada registro.
  • FK: chave estrangeira, relaciona uma tabela a outra.
  • UNSIGNED: tipo numérico sem valores negativos.
  • AUTO_INCREMENT: identificador gerado automaticamente.
  • Campo derivado: valor calculado pelo banco de dados.
  • TINYINT(1): indicador lógico, em que 0 representa não e 1 representa sim.

Os exemplos de valores deste documento são fictícios. Os atributos com dados pessoais devem ser utilizados somente para as finalidades informadas e com os cuidados previstos na LGPD.

22. Regras gerais do sistema

  • O fiado é permitido somente para clientes conhecidos e autorizados pela adega. O cliente deve estar desbloqueado e possuir limite disponível suficiente para a operação.
  • O valor total dos pagamentos de uma venda deve corresponder ao valor total da venda. Quando houver pagamento dividido, cada forma deve registrar somente a parcela correspondente.
  • O atributo item_fiado.id_item_venda identifica uma linha de venda destinada integralmente ao fiado. O modelo atual não representa uma parte do valor de uma mesma linha no fiado.
  • Produtos de categorias restritas exigem conferência de maioridade e cumprimento da legislação aplicável.
  • Lotes vencidos não devem ser comercializados. O controle deve considerar a data de validade do lote.
  • O saldo de estoque deve ser atualizado por movimentações registradas, mantendo histórico de entradas, saídas, perdas e ajustes.
  • O fechamento do caixa deve comparar o valor esperado com o valor contado, registrando diferenças e justificativas.
  • O acesso a dados pessoais deve respeitar a LGPD, com acesso limitado às finalidades necessárias e proteção das informações.

23. Observações sobre o modelo

  • O modelo lógico XML enviado possui 19 tabelas, incluindo log_acesso, que é uma tabela técnica de auditoria.
  • O relacionamento entre produto e estoque é 1:1, pois estoque.id_produto é único.
  • O relacionamento entre venda e fiado é 1:0..1, pois uma venda pode não gerar fiado e cada fiado pertence a uma única venda.
  • O atributo vl_diferenca é calculado a partir de vl_contado menos vl_esperado.
  • As cardinalidades listadas reproduzem o XML fornecido. O diagrama visual do brModelo deve representar os mesmos relacionamentos.
  • Os tipos de dados devem ser conferidos com o script SQL utilizado na entrega. Se o SQL for alterado, este dicionário também deverá ser atualizado.
