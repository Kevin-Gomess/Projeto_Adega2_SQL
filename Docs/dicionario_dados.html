Dicionário de Dados - Adega do Tonho

Este documento apresenta as tabelas, os atributos, os tipos de dados, as descrições e as regras de negócio do banco de dados da Adega do Tonho.

SGBD: MySQL 8.0

Modelo de referência: Modelo lógico do script docs/script.sql (versão 2.0, com a tabela nota_fiscal), com 22 tabelas.

1. Convenções utilizadas

  • PK: chave primária, identifica cada registro.
  • FK: chave estrangeira, relaciona uma tabela a outra.
  • UNSIGNED: tipo numérico sem valores negativos.
  • AUTO_INCREMENT: identificador gerado automaticamente.
  • Campo derivado: valor calculado pelo banco de dados.
  • TINYINT(1): indicador lógico, em que 0 representa não e 1 representa sim.

Os exemplos de valores deste documento são fictícios. Os atributos com dados pessoais devem ser utilizados somente para as finalidades informadas e com os cuidados previstos na LGPD.

23. Tabela: Nota_Fiscal

Cadastro e controle interno dos documentos fiscais de entrada (ligados a uma compra) e de saída (ligados a uma venda). A tabela só registra o documento: não emite NF-e/NFC-e nem consulta ou autoriza documentos na SEFAZ. Cada compra ou venda tem no máximo um documento.

Atributo Tipo de dado Descrição Regra de negócio associada
id_nota_fiscal BIGINT UNSIGNED Identificador interno do documento fiscal. Chave primária; gerada automaticamente.
tp_operacao ENUM('ENTRADA','SAIDA') Indica se o documento acompanha uma compra ou uma venda. Obrigatório; ENTRADA exige id_compra e SAIDA exige id_venda.
tp_modelo ENUM('NF_E','NFC_E','CUPOM_FISCAL','OUTRO') Modelo do documento fiscal. Obrigatório; padrão OUTRO.
nr_numero VARCHAR(44) Número ou identificador informado no documento. Obrigatório.
nr_serie VARCHAR(10) Série do documento fiscal, quando aplicável. Opcional.
cd_chave_acesso CHAR(44) Chave de acesso de 44 dígitos, quando disponível. Opcional; única.
dt_emissao DATETIME Data e hora de emissão informadas no documento. Opcional.
vl_total DECIMAL(12,2) Valor total registrado no documento. Obrigatório; não pode ser negativo.
st_documento ENUM('SEM_VALIDACAO','AUTORIZADA','CANCELADA','DENEGADA') Situação de controle do documento. Obrigatório; padrão SEM_VALIDACAO. A autorização deve ser confirmada fora do banco (SEFAZ).
ds_observacao VARCHAR(255) Observações sobre o documento fiscal. Opcional.
id_compra INT UNSIGNED Compra relacionada, para documento de entrada. Chave estrangeira para compra; única; nula para documento de saída.
id_venda BIGINT UNSIGNED Venda relacionada, para documento de saída. Chave estrangeira para venda; única; nula para documento de entrada.
dt_cadastro DATETIME Data e hora do registro no sistema. Preenchida automaticamente.

25. Regras gerais do sistema

  • O fiado é permitido somente para clientes conhecidos e autorizados pela adega. O cliente deve estar desbloqueado e possuir limite disponível suficiente para a operação.
  • O valor total dos pagamentos de uma venda deve corresponder ao valor total da venda. Quando houver pagamento dividido, cada forma deve registrar somente a parcela correspondente.
  • O atributo item_fiado.id_item_venda identifica a linha da venda que teve valor lançado no fiado e item_fiado.vl_fiado diz quanto daquela linha foi lançado (no máximo o subtotal da linha). A soma dos vl_fiado da venda é igual ao total do fiado.
  • Produtos de categorias restritas exigem conferência de maioridade e cumprimento da legislação aplicável.
  • Lotes vencidos não podem ser comercializados: o trigger de item_venda e a procedure de abertura de garrafa recusam lote vencido.
  • O saldo de estoque e o saldo do lote só mudam por movimentações registradas (trigger), mantendo histórico de entradas, saídas, perdas e ajustes. Movimentações, itens de venda, pagamentos e itens de fiado não podem ser alterados nem excluídos.
  • O fechamento do caixa (procedure sp_fechar_caixa) calcula o valor esperado: troco inicial, mais vendas e recebimentos de fiado em dinheiro, mais suprimentos, menos sangrias e despesas. Compara com o valor contado e registra a diferença e a justificativa.
  • Cada documento fiscal registrado em nota_fiscal é de entrada (ligado a uma compra) ou de saída (ligado a uma venda), nunca aos dois; cada compra ou venda tem no máximo um documento e a chave de acesso não se repete. O banco só registra o documento: a emissão e a autorização na SEFAZ são feitas fora dele, e os documentos migrados entram como SEM_VALIDACAO.
  • O acesso a dados pessoais deve respeitar a LGPD, com acesso limitado às finalidades necessárias e proteção das informações.

26. Observações sobre o modelo

  • O banco possui 22 tabelas: as 19 entidades de negócio (as 18 anteriores mais nota_fiscal) e as tabelas de apoio log_acesso (auditoria), garrafa_aberta (volume das garrafas abertas) e movimentacao_caixa (suprimentos, sangrias e despesas).
  • O relacionamento entre produto e estoque é 1:1, pois estoque.id_produto é único.
  • O relacionamento entre venda e fiado é 1:0..1, pois uma venda pode não gerar fiado e cada fiado pertence a uma única venda.
  • O atributo vl_diferenca é calculado a partir de vl_contado menos vl_esperado.
  • As cardinalidades listadas correspondem às 32 chaves estrangeiras do script SQL. O diagrama do brModelo deve representar os mesmos relacionamentos.
  • Os tipos de dados foram conferidos por programa com o script SQL (docs/script.sql, versão 2.0). Se o SQL for alterado, este dicionário também deverá ser atualizado.
